## 2. 工程包：一次真实的「解压后缺文件」事故与修复

### 现象

D 盘那份工程包最初只有 **53 个文件 / 181.8 MB**，`pingpang\public_data\videos\` 是一个**空目录**——连 `0度` / `45度` / `90度` 三个机位子目录都不存在。`basketball\public_data\videos\` 里 2 个视频在，但文件名是乱码：

```
2025-26NBA_甯歌璧沖榄旀湳vs鍑皵鐗逛汉_钄″嚡鑷_seg1_main.mp4      ← 实际是 2025-26NBA_常规赛_魔术vs凯尔特人_蔡凯臣_seg1_main.mp4
```

### 根因

`participant.zip` 里的中文条目名是 **UTF-8 字节，但没有设置 ZIP 的 UTF-8 语言编码标记位（`flag_bits` 的 `0x800`）**。Windows 资源管理器、PowerShell `Expand-Archive`、.NET `ZipFile` 在这时都会回退到系统 ANSI（简中为 GBK/CP936）解码，得到 `0搴?` 这类含非法字符的名字，而**含非法字符的条目会被直接静默跳过**。

所以丢的不是「文件坏了」，而是这 15 个中文名条目**根本没被写出来**——解压过程既不报错也不提示。

> 用 `zipfile` 读元数据可以看到这 15 个条目确实在压缩包里；对同一条目做 `cp437 编码 → utf-8 解码` 就能还原出 `0度` 这样的正确名字。

### 修复

1. 用 `tools/unpack_participant.py` 从原始 `participant.zip` 正确解压，得到 **68 个文件**、`0度`/`45度`/`90度` 三个子目录、15 个乒乓球验证集视频，中文名正确。
2. 把这 3 个子目录复制进 D 盘工程包。
3. 把 D 盘篮球那 2 个乱码文件名改成 manifest 里的正确名（内容未动，改前后与正确副本 SHA256 逐字节一致）。

### 修复后校验（可复核）

```
pingpang   : manifest 声明 15 条视频，缺失 0 条
basketball : manifest 声明  2 条视频，缺失 0 条
乒乓球视频文件数: 15
工程包文件总数: 68
```

再跑框架自带的完整性校验（只管 `core/` 与框架脚本）：

```
$ python participant/pingpang/integrity.py --verify     → 完整性校验通过
$ python participant/basketball/integrity.py --verify   → 完整性校验通过
```

**注意：`integrity.py` 校验不到 `public_data/`。** 视频缺失不会让完整性校验失败，一定要另外跑：

```bash
python tools/check_dataset.py participant
```
